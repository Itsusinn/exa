# Dungeon 3D — Godot + Rust

桌面优先的第一人称多人方块游戏。Godot **Forward+ + SDFGI** 负责画面、场景、输入和 UI；Rust 通过 GDExtension 保留模拟、客户端预测和经过证书验证的 Quinn/QUIC。独立 Rust 服务端使用 hecs，不依赖 Godot。

客户端统一使用 Godot，旧桌面入口和自研渲染器已移除。尚待完整实机键鼠及窗口交互验收，架构与验收状态见 [PLAN.md](PLAN.md)。

## 运行

使用 `rust-toolchain.toml` 指定的 stable 工具链、`just`、Godot **4.7.2**。Rust 绑定固定为 `godot = 0.5.5`，使用 `api-4-7`。在 PowerShell 设置 `GODOT_BIN` 为 Godot 可执行文件路径；使用 .NET 编辑器时还需可用的 .NET SDK（本机为 8.0.427）。游戏本身不使用 C#。在仓库根目录分别启动：

`scripts/` 的全部可执行入口均为 Cargo script，先安装 `rustup toolchain install nightly --profile minimal --component rustfmt --component clippy`。统一调用形式为 `cargo +nightly -Zscript scripts/<name>.rs`；`just` 已封装这些命令。nightly 只用于脚本，脚本内部构建游戏时仍遵循仓库的 stable 工具链并使用两个构建任务。`godot.rs` 负责构建、运行、测试与导出，`godot-mcp.rs` 负责可选编辑器工具，`dev.rs` 负责联合启动，`thermo_oracle.rs` 负责参考数值生成；共享 Rust 实现在 `scripts/support/`，没有 PowerShell 脚本入口。

```sh
just server
just client
```

也可一条命令启动独立服务端并让客户端自动连接：

```sh
just dev
```

`just dev` 先构建，等待本次服务端写好证书并开始监听，再启动客户端；关闭客户端后，服务端正常保存并退出。支持 `CDDA_BIND`（默认 `127.0.0.1:9876`，端口不能为 0）、`CDDA_SAVE_PATH`、`CDDA_CERT_PATH` 和 `CDDA_IDENTITY_PATH`。绑定 `0.0.0.0` 或 `::` 时，本机客户端使用对应回环地址连接。启动失败会报错，不会连接已有的其他服务端。该 Windows 启动器为 `scripts/dev.rs` Cargo script，需要额外安装 `rustup toolchain install nightly --profile minimal`；游戏本身仍用仓库的 stable 工具链构建。终端显示两端日志，启动器强制 `server=info` 以确认就绪；Ctrl+C 会关闭客户端并通知服务端保存。

客户端启动后显示主界面：**单人游戏、多人游戏、设置、退出游戏**。单人游戏自动在后台启动内置 Rust 权威服务端，通过回环地址的随机端口和经过证书验证的 QUIC 连接；无需单独运行 `just server`，支持现有战斗、敌人、拾取和背包。多人游戏页填写地址、昵称和服务端当前证书，支持同服最多 16 人。

`just client` 会先编译并安装扩展 DLL；重新编译前关闭使用该 DLL 的游戏或编辑器。直接联机可执行 `cargo +nightly -Zscript scripts/godot.rs run --connect`，直接进入单人游戏使用 `cargo +nightly -Zscript scripts/godot.rs run --singleplayer`。

`cargo +nightly -Zscript scripts/godot.rs --help` 查看全部操作。Windows 下 `GODOT_BIN` 和 `DOTNET_ROOT` 优先读取当前进程环境，未设置时直接读取用户环境配置；参数作为独立进程参数传递，支持含空格的路径。`just scripts-check` 检查四个脚本及共享模块的格式和严格 Clippy，已包含在 `just check`；`just scripts-test` 验证导出过滤和文件复制。`cargo +nightly -Zscript scripts/godot-mcp.rs --check` 只检查 MCP 工具与 .NET 版本，不安装插件或启动编辑器。

设置包含视野、鼠标灵敏度、全局光照和全屏，保存在 Godot 用户目录的 `settings.cfg`。视觉采用自然写实方向：石材、旧木板、树皮与草地 PBR 表面，柔和日光；UI 使用炭灰与灰绿色、细边框、小圆角和轻微反馈。菜单背景来自项目场景实机渲染，游戏内菜单模糊当前世界；设置、HUD、背包与快捷栏共用 `godot/src/interface_theme.gd` 主题。

设置页新增抗锯齿选择：关闭、FXAA、MSAA 2×、MSAA 4×、TAA，即时应用并保存；默认 MSAA 4×，旧设置没有该字段或值无效时使用默认值。MSAA 主要平滑几何轮廓，保留纹理清晰度；FXAA 开销较低但较柔和；TAA 改善细节闪烁，移动时可能模糊/拖影。各模式互斥，仅作用于 3D 视口，HUD 不经过额外全屏模糊。保留现有纹理 mipmap 与法线方差粗糙度过滤。

实现参考 Horizon 的 `world_post.wgsl` / `graphics_ui.rs` 中 AA 模式与时间历史职责，以及 Iris `shaderpack/properties/ProgramDirectives.java` 对光影包 TAA 渲染目标的兼容处理；本项目使用 Godot 自带 AA，不移植 wgpu/Java 管线、不叠加光影包 AA。原理和取舍见 [Godot 3D 抗锯齿说明](https://docs.godotengine.org/en/stable/tutorials/3d/3d_antialiasing.html)。`visuals.gd` 输出五档静态对照与 TAA/MSAA 4× 平移过程截图。

```sh
just demo
```

`--demo` 是可移动、可跳跃的离线三维漫游场景，用同一套碰撞规则；其中的角色是静态展示。战斗、拾取、聊天和其他玩家需要连接服务器。

## 操作

进入游戏后自动捕获鼠标，按 Esc 打开游戏菜单并释放鼠标。菜单提供继续、设置、返回主界面、退出游戏；再次按 Esc 可继续。背包、箱子、聊天等 UI 打开时释放鼠标，关闭后自动恢复捕获。失去窗口焦点时释放鼠标并清空按键，重新聚焦且没有 UI 打开时自动捕获。菜单打开时世界仍在运行，单人和多人均不暂停模拟。

| 输入 | 动作 |
|---|---|
| 鼠标 | 第一人称转向、抬头与低头 |
| WASD / 方向键 | 相对朝向连续移动 |
| Space | 跳跃；需要落地后才能再次起跳 |
| 左键 | 破坏方块或拆除空设备，收入物品栏 |
| 右键 | 在目标表面放置当前快捷栏方块或设备，消耗 1 个 |
| R | 切换待放置管道的 X/Y/Z 轴向 |
| P | 持管道时切换两点铺管模式；再次按下取消 |
| B | 持储罐或密闭罐时打开建造规格面板 |
| J | 在线单人或多人中打开二元蒸馏设计器 |
| F | 面向目标的近战攻击 |
| G | 拾取附近物品 |
| E | 打开附近箱子或工业设备信息，Esc 关闭 |
| Tab | 打开 / 关闭背包、日志和聊天 |
| 1–9 / 滚轮 | 选择 / 循环切换快捷栏槽位 |
| 物品栏左键 / 拖动 | 移动、合并同类物品，整组不同物品交换槽位 |
| 物品栏右键 | 选中半组；已有选择时向目标放入 1 个 |
| Shift + 点击 | 背包与快捷栏快速转移；打开箱子时快速存取 |
| Esc | 打开游戏菜单 / 返回上一级 / 继续游戏 |
| 设置页视野滑块 | 调整视野角度 |
| 聊天框 + Enter | 发送聊天 |
| / | 打开聊天并预填指令前缀 |
| 飞行时 Space / Shift / Ctrl | 上升 / 下降 / 3 倍加速，松键悬停 |

菜单和聊天不触发移动。联机世界不会因为本地打开菜单而暂停。受击生命值归零后在空闲出生点复活，当前携带物品保留。

### 玩家指令

单人和多人中的所有玩家均可在聊天框输入指令，按 Enter 执行；按 `/` 可直接打开输入框，Esc 返回游戏。指令由服务端执行，反馈显示在自己的行动记录中，不广播给其他玩家；普通聊天仍共享。离线 `--demo` 展示不支持指令。

| 指令 | 效果 |
|---|---|
| `/help` | 查看指令帮助 |
| `/spawn` | 返回出生区域的空闲出生点，保留生命、背包和飞行状态；无可用位置时提示失败 |
| `/tp x y z` | 传送自己到脚底坐标，如 `/tp 28.5 20 32.5` |
| `/tp ~ ~5 ~` | 相对当前位置向上移动 5 米；各轴支持 `~` 或 `~偏移` |
| `/fly` | 切换自己的飞行状态 |
| `/fly on` / `/fly off` | 开启 / 关闭飞行 |
| `/industry kit` | 原子领取 2 个储罐和 16 段管道测试补给 |

飞行保留方块、角色、未知区块与世界边界碰撞，WASD 水平移动，Space 上升、Shift 下降、Ctrl 加速至 3 倍；松键悬停。HUD 标记当前飞行状态。关闭后恢复重力；死亡复活、断线重连和重启后默认关闭，飞行开关不写入存档。传送位置沿用现有玩家存档保存，不改变存档格式。

传送会生成目标附近地形并分批同步、卸载远处区块，拒绝非有限数字、越界、方块或角色占用的落点；等待目标附近区块时暂停本地预测，权威位置到达后重置画面插值。改变状态的指令每人间隔至少 0.5 秒，传送落点检查失败也计入间隔。

## 当前 3D 范围

方块接触遮蔽参考 `refs/horizon/crates/horizon-client-render/src/mesher/lighting.rs` 的邻格采样思路，使用一格 halo 的边/角遮蔽；跨区块加载、修改、卸载会使 26 个邻区块失效。遮蔽通过 UV2 独立传给 Godot AO，保留贴图颜色和太阳直射层次，未知区块与水不作为遮蔽物。非地形网格默认无遮挡。

每个方块面携带四个角的遮挡数量，在着色器内使用平滑双线性插值，消除两个三角形之间的明暗折痕；接地与凹角渐暗，共面接缝平滑，几何、法线方向和碰撞形状不变。`contact_ao_strength` 默认 0.85，设为 0 可单独关闭方块 AO。图形检查 `godot/tests/visuals.gd` 会输出石屋及台阶的同视角 `*-ao-off.png` / `*-ao-on.png`，两组对照均关闭 SSAO 以区分两种遮蔽。

纹理保留现有 CC0 PBR 素材，并用连续世界坐标产生小幅明暗/粗糙度变化，避免逐块随机颜色的拼接感；衍生岩石、树皮和树叶材质也读取对应粗糙度贴图。外露凸棱通过邻格检查生成四边掩码，在约 3.5 厘米宽度内平滑偏转着色法线，保留贴图凹凸；共面内部接缝、水面和非地形网格不倒角，远处亚像素倒角逐渐衰减。该效果仅改变受光，轮廓、投影几何和碰撞仍是直角，不是实体圆角或视差映射。`bevel_width=0` / `material_variation=0` 可分别关闭倒角与材质变化；`visuals.gd` 输出 `steps-material-*`、`detail-material-*` 同视角对照。

光照参考 `refs/Iris/common/src/main/java/net/irisshaders/iris/shadows/ShadowMatrices.java` 的阴影稳定性关注点及 `vertices/NormalHelper.java` 的法线处理职责，在 Godot 内采用四级混合太阳阴影、4096 阴影图、法线方差粗糙度过滤及较轻的 SSAO。保留 Forward+ / SDFGI 与 ACES；这是针对现有渲染器的独立实现，不加载 Iris shader pack、不移植其 Java/OpenGL 管线，也不宣称复现某个光影包。程序化颗粒按像素覆盖范围衰减，减少远景闪烁。

- 按需扩展的方块世界，X/Z 支持正负坐标，Y 高度为 128，按 16×16×16 分段传输。新世界的出生区域也使用自然生成；先生成 64×128×64 范围，陆地不足时有限扩展搜索，探索时继续生成新区块。水平技术范围为 `[-32768, 32768)`，用于控制 f32 物理与渲染精度，垂直范围为 `[0, 128)`。
- 自然起伏地形、六类生态、河谷、浅湖、树林与洞穴，未探索区域按条件生成村庄和城堡。未实现游泳；固定石屋、平台和水池仅保留在离线展示场景或旧存档中。
- 透视相机、深度遮挡、隐藏方块面剔除、PBR 材质、太阳阴影、SDFGI、SSAO、ACES 色调映射和距离雾。地形按区块生成网格，只在地图版本变化时重建；动态角色独立更新。保留现有方块几何与角色造型，写实化主要体现在材质、光照和 UI。SDFGI 替代原 WGSL GI，并非原算法的逐像素复现；动态实体接受 GI，但不承诺像静态地形一样参与 SDFGI 遮挡。
- 连续移动与重力在客户端、服务端共用 30 Hz 固定步长规则，使用 Rapier 3D 0.36.1 角色控制器处理地面、墙体、头顶、实体碰撞和未知区域阻挡。
- 第一人称相机按渲染帧率在相邻两次已完成的本地运动状态间插值，消除 30 Hz 移动的阶梯感；位置显示延迟一个模拟步（约 33 毫秒），鼠标转向即时响应。权威位置纠正、复活和切换会话时重置插值。
- 服务端权威近战、敌人追踪和攻击、拾取、背包、聊天、复活和多人同步。敌人使用直接追踪和视线判定，尚无跨高度的完整寻路。
- 玩家物品栏为 27 格背包 + 9 格快捷栏，每格最多 64 个；快捷栏是物品栏的前 9 格，不复制物品。支持拖放、点击移动、拆分、合并、整组交换和 Shift 快速转移。底部显示快捷栏、数量及当前物品名称，1–9 或滚轮切换；选中的方块可右键放置，暂不增加装备或攻击效果。背包满时拾取物留在地面；Esc 首先取消选中，再关闭界面。
- 箱子是有碰撞的容器方块，新地图按实际地表在出生点附近选择安全位置生成一个空箱子，坐标不再固定。准星对准箱子且距中心不超过 3.5 米时按 E 打开，与物品栏共用格子界面，支持跨区域拖放、单个或整组存取（界面每次最多 64）。为兼容既有存档，箱子仍容纳 24 类物品，每类最多 999 个；同类自动归并，空类移除。多人共享，由服务端检查距离、遮挡、数量、箱子版本和背包版本，失败不改变任何一端。离开范围、被遮挡、死亡、失焦或断线会关闭箱子；打开界面时世界仍运行。
- 单人及多人支持生存式方块编辑：每次点击破坏或放置一个方块，交互距离为视线 4.5 米，服务端成功操作间隔至少 0.2 秒。破坏直接收入对应方块，背包满则拒绝破坏；放置消耗当前快捷栏的 1 个方块。草方块、泥土、石块、原木、树叶、木板、空箱子及下文新增的 15 种自然方块可操作，水与世界底层不可破坏，水格不能被覆盖。非空箱子必须先取空；破坏空箱子会关闭其他玩家正在查看的该箱子。禁止越界、穿墙、覆盖已有方块或地面物品，以及在玩家/NPC 身体内或设备占用格放置。地形变化更新共享碰撞，并广播变化区块；客户端仅重建该区块及相邻区块网格。编辑后的地图、箱子与玩家物品共同持久化，旧地图按下文版本 12 策略迁移。离线 `--demo` 仍只用于漫游。
- 本轮不包含合成、工具耐久、动态流体、昼夜系统或完整账号认证。原先的饥饿、口渴等静态 HUD 已移除，避免展示尚未接通的玩法。

## 地形与生态

世界高度为 128，新世界从出生区域起统一按种子及绝对世界坐标确定性生成，不再预置旧石屋、平台、水池或 112 格过渡带，多尺度噪声组合温度、湿度、山脊和弯曲河谷；包含草原、阔叶林、针叶林、沙漠、湿地和雪地，浅湖/冰面、不同高度树冠、地下洞室与相连洞道。高处出现积雪，地下有玄武岩层及煤、铁、铜矿脉。生态边界使用连续气候场，地表方块按生态分类；不模拟真实侵蚀或生态演替。

新世界自动寻找有地面支撑、头顶空间足够的干燥出生位置，避开水面、冰面、树冠和实体占位；`/spawn` 与死亡复活使用相同检查。箱子、补给和初始敌人随实际地表布置。初始 4×4 区块列陆地不足时逐圈扩展，最多搜索 12×12 列；仍无足够安全位置则报错，不铺设人工平台。默认种子仍是 `12345`，同一种子的新地图保持一致。已有存档的地形、建筑和角色位置继续保留；离线 `--demo` 仍是独立的固定展示场景。

`just godot-natural-spawn` 在隔离世界的实际图形窗口验证出生地形、行走/跳跃、补给、`/spawn` 与保存重开，截图输出到 `target/natural-spawn-*/`。Rust 测试另覆盖多种种子、16 人出生及不安全地表拒绝。

新增 **15 种方块**：沙子、砂岩、砾石、黏土、雪块、冰块、苔石、玄武岩、白桦原木、白桦树叶、松木、松针叶、煤矿石、铁矿石、铜矿石。均可破坏收取、放置、存入箱子并保存；矿石目前掉落对应矿石方块，不增加冶炼、合成或工具体系。沙与砾石暂不受重力影响，冰保持普通实体碰撞；水沿用静态浅水规则，无游泳、流动或冻结模拟。

新自然材质使用自有程序化颗粒、岩层和矿脉纹理，并复用已有 CC0 草叶/树皮/石材法线；无需下载新资产。树木根与树冠按邻区坐标一起计算，不受探索顺序影响。已探索旧区块不会重新生成，因此旧地图需要走向未探索区域才能看到新生态；新旧生成区域边界可能出现高度接缝。

世界版本 **12**、区块归档版本 **3** 保留旧格式标记与稳定方块名称。版本 1–6 完整验证后保留原 0–31 层，上方 32–127 层补空气；版本 7 及以后保留原有 128 层，下一次保存升级。版本 6 的世界清单备份为 `world3d.v6.bak`，同时独立复制 `world3d.v6.bak.chunks/`、`.players/`、`.entities/`；其他版本同样备份其存在的归档目录。回退时恢复备份清单及目录到原名称；新版缺失分段仍视为损坏，不会按旧版补齐。迁移不重置建筑、箱子、背包、玩家或怪物死亡状态。

运行 `just godot-ecology` 可在独立测试世界依次访问六种生态、检查 128 格区块缓存/卸载、保存重开并生成实际 Forward+ + SDFGI 截图。坐标由 Rust 的固定种子测试生成，输出位于 `target/ecology-graphics-*/`；不触碰真实 `save/`。

## 工业设备、相平衡与换热

单人和多人共用 Rust 权威设备系统。聊天输入 `/industry kit` 领取常压水罐、管道、测试泵、阀门、密闭罐、双流换热器和管架；这是测试补给，不消耗矿石，也不代表已有合成或工业生产系统。物品栏空间不足时整份补给拒绝发放。

- 选择快捷栏中的设备，准星指向表面后右键放置，消耗 1 件；预览显示放置位置及本地占位检查，最终由服务端确认。
- 储罐预留 2×3×2 格空间；管道占一格，按 R 轮换 X/Y/Z 轴向。细管与罐体使用 Rust 共享的局部碰撞形状，客户端预测、服务端运动与选取共用规则。
- 左键瞄准设备拆除并收回 1 件。非空设备、满背包、版本冲突、超距或遮挡时拒绝；普通方块也不能放进设备占用格。
- 对准设备按 E 查看内容、液位、罐口压力、温度和流量；泵面板可启停和反向，阀门面板可调开度。控制由服务端校验距离、遮挡和修订号，运行时的物料变化不使控制修订号失效。
- 泵壳四周的黄色箭头表示设定的输送方向，反向设置经服务端确认后翻转；停泵时仍可见，建造预览也显示方向。储罐使用 96 段圆周与平滑侧面法线，端盖保持清晰边缘；显示网格按形状复用。
- 设备拥有独立稳定 ID 与修订号，跨区块保存一份；附近区块订阅发送设备列表，远处卸载和切换会话清理显示与碰撞数据。

第二阶段采用单一液态水的有限范围模型：开口罐保存摩尔数和内能，密度固定为 1000 kg/m³，比热固定为 4180 J/(kg·K)，温度范围 273.15–373.15 K。罐容积约 7125 L，端口位于底部以上 0.5 m，管输不能抽走端口以下约 1272 L 的余液。测试排水指令可移除全部库存。

搭建两个同高储罐，在相对的 X 轴端口之间用连续的管道、泵和阀门连接。相邻端口必须重合且相向；泵和阀门占一格，可按 R 切换轴向。泵默认关闭，启用后提供 50 kPa 测试压升；关闭时隔离输送，阀门开度为零时严格停止流动。不带泵的连通储罐按液位压差自然输送。每段管线使用简化阻力，流量上限 20 L/s；不模拟管内充填、局部管压、相变、真实泵曲线或外部燃料消耗。

在近处瞄准储罐，使用面板显示的设备 ID：

```text
/industry fill <id> <升数> [温度K]
/industry drain <id>
```

注水默认 293.15 K，注排作为外部物料与能量交换记账；测试泵输入功单独累计。内部转移同时守恒物料与“内能 + 重力势能”，包括压差耗散转为内能。未知物料、超出模型范围或计算失败时保留库存并显示暂停原因；故障按水力及热耦合连通组隔离。管道、泵、阀门和换热流道没有独立持液容积，拆开管线只改变连接，不丢弃罐内物料。

第三阶段新增 **密闭罐**（2×3×2 格）与 **双流换热器**（2×1×3 格），均固定沿 X 连接。密闭罐首批支持正丁烷 `icheme:n_butane`、正戊烷 `icheme:n_pentane`，采用参考项目的 PR78 状态方程、热容与二元相互作用数据，通过气液平衡从保存的组分摩尔数、内能和容积恢复温度、绝对压力与相量。旧常压水罐仍使用上面的单液模型，原水库存、内能和温度不会因升级切换物性；不允许水与烃在同一物料流道中混合。

瞄准**空密闭罐**执行测试装料，数量单位为摩尔，温度单位为 K；至少一种组分大于零。下面给出等摩尔二元混合物示例：

```text
/industry charge <id> 1000 1000 320
/industry heat <id> 100000
/industry heat <id> -100000
/industry drain <id>
```

装料按固定容积、给定温度和组分求初态，只接受能求解的状态；`heat` 的单位是焦耳，正值加热、负值冷却。注排与热量交换分别记账，失败不改变库存或账目。测试热源没有燃料消耗，也不模拟沸腾到环境的水蒸气；烃类相变只发生于密闭罐与其对应的物性计算中。

换热器的 A（橙色）与 B（蓝色）流道各有一对 X 向端口，相隔两格 Z，分别接入两个直线回路。两侧可以使用不同物料，**只交换能量，不交换组分**。按 E 打开面板，可选择关闭、手动换热比例或 A 侧出口温度目标；达不到目标时显示受限。当前每条罐间流路支持一个换热器，串联多个会明确暂停该组并保留库存，尚未实现多换热器耦合网络。调节没有 PID、独立传感器附件、燃烧炉、真实旁路管路或执行器延迟。任一侧无流量时换热功率为零；停流或不可测读数明确标识，不以旧温度冒充当前读数。控制编辑草稿与运行刷新分离，点击应用后等待权威回显。

工业计算使用独立的 0.2 秒切片，服务端最多运行一个后台任务，不积压补算任务；玩家运动仍为 30 Hz。计算过慢时工业时间减慢，不追赶积压时间。结果提交前核对事实修订号、设备身份与守恒，建造、拆除、注排或改设置后，旧任务结果被丢弃。客户端卸载远处区块不停止工业计算；退出时等待已有任务结束并丢弃未提交结果，离线不补算。

验证入口为 `just godot-industry`（headless）及 `cargo test -p client --test industry --jobs 2`（真实 QUIC）。实际图形检查使用 `just godot-industry-graphics`，启动器使用 console 可执行文件等待退出并返回验证结果；测试生成 `target/` 下的隔离世界和截图，不修改真实存档或用户设置。具体通过项与未验收范围见 PLAN。

最小回路验证使用 `just godot-industry-flow` 或 `just godot-industry-flow-graphics`，先执行真实 QUIC 回路测试，再复制隔离存档运行 Godot 场景检查。

第三阶段验证使用 `just godot-industry-thermal` 或 `just godot-industry-thermal-graphics`，覆盖二元相态、四口换热、两客户端控制冲突、停流、保存重开及图形面板。烃类模型接受 293.15–400 K、1 Pa–2 MPa，低于源数据 100 Pa 的部分是为小量注入空罐提供的稀薄气延拓，没有新增实验认证。PR 液体体积未做密度校准；密闭罐重力势能按固定罐体质心近似。双流换热使用 UA=1500 W/K、焓曲线等效容量率与同/逆流 ε-NTU，不含壁面蓄热；瞬时输送和换热会有限回退以保持可解状态。详细来源、能量基准和数值限制见 [物性说明](server/assets/thermo/README.md)，实际验收结果见 PLAN；本阶段不是参考工程完整物性库、固相或反应系统的移植。

第四阶段 **4A 管路建造** 支持水平和竖向弯管，可绕过障碍并跨区块、跨高度连接设备。每段管只连接它保存的两个面，并排线路不会自动串接。旧管道保留原轴向，普通逐格放置与拆除继续可用。

1. 先放好要连接的设备，快捷栏选择管道，按 **P** 进入铺管模式。
2. 近距离瞄准设备或既有管的**可见空闲接口**，右键选择起点并等待确认。端点目前必须属于已有设备，不从裸地形创建自由端点。
3. 移动到另一设备，瞄准它的空闲接口，查看整条路线、管段数量和材料需求，再右键提交。起点最多保留在 32 米范围内，终点保持 4.5 米交互距离；每条路线最多放置 32 个新管段。
4. 服务端重新检查接口、整条路线、障碍、角色占位和背包版本，从整个背包扣除每段一件管道；成功才一次放置全部管段。失败不部分扣料，重复请求不重复建造。按 **Esc / P** 取消；切换物品、失焦、死亡、断线或离开起点范围也会清理草稿。

寻路只使用客户端已知区块，采用有界搜索；未知区域或没有合适路径时显示拒绝原因。单层管架占一格的下半层，可与同格的一根水平直管或水平弯管共存，先放管架再铺管最直接；竖管、泵、阀门不能与管架共格。拆架前先拆管。它不是参考项目的多槽偏心管架。

跨高度回路计入高程压头与势能；含真实烃类物性的线路采用供体相密度的集中近似，若不同密度造成流向无唯一自洽解释，会保留整组事实并暂停。管内仍无独立持液量，不建立沿程压力场，也不模拟开口喷流。三通分流与任意多换热器耦合属于后续阶段。

运行 `just godot-industry-route` 或 `just godot-industry-route-graphics` 可验证原子铺管、弯头、单管架、跨高度输送和保存重开。脚本入口为 `cargo +nightly -Zscript scripts/godot.rs industry-route[-graphics]`。

### 参数化罐体与换热单元检查（4B）

快捷栏持储罐或密闭罐时按 **B**，选择直径 **2–6 格**和高度 **3–12 格**，应用后查看完整建造预览，右键放置。每台仍消耗一件测试设备；建成后尺寸固定，空罐可拆除返还一件再重建。默认 2×3×2 与旧罐一致，容量约 7125 升。容量沿用本项目圆柱模型：内半径为直径的一半减 0.1 米，有效高度为总高减 0.2 米；最大规格容量约 31.18 万升。共享碰撞、端口、液位压头、密闭罐体积和能量计算都使用实例规格。两个端口仍位于 ±X 侧、离底 0.5 米，按格面中心对齐，可用 P 铺管连接。换热器尺寸与额定 UA 保持既有值。

瞄准双流换热器按 **E**，点击“检查换热单元结构”。固定设计要求四口连接四个独立罐：**A0 / B0 为进料线，各有一泵一阀；A1 / B1 为出料线**，同侧的两罐须为相同类型。检查实际管路、缺件、回环、重复部件、混接罐型及泵方向，列出设备 ID；关泵和关阀不影响结构是否齐全，运行结果仍看仪表。该诊断不限制设备运行，不代表热工性能达标。

检查由服务端按请求进行，客户端附近区块之外的设备也参与。报告不写入存档，关闭面板或重连后可重新检查；工业设备建造/拆除、规格或泵方向改变会使已检查报告失效。当前采用全世界结构签名，因此无关远处的结构修改也可能使报告过期；物料、温度、开度和启停变化不会。每位玩家只缓存最新报告，重复请求回放，匹配遍历受 1024 台设备上限约束。暂不包括整厂复制、三通旁路、任意喷嘴、卧式罐或蒸馏整机。

`just godot-industry-design` / `just godot-industry-design-graphics` 验证规格草稿、真实建造、结构检查、报告失效和保存重开；后一命令启动实际图形窗口。底层入口为 `cargo +nightly -Zscript scripts/godot.rs industry-design[-graphics]`。

### 二元蒸馏设计器（5A）

进入单人或多人世界后按 **J** 打开设计器。输入进料摩尔流量、丁烷摩尔分数、进料温度、塔压、理想板数、进料板、回流比和馏出比例，点击计算。首批只支持正丁烷/正戊烷、单进料、固定压力、全凝器和平衡再沸器；理想板数 **2–12** 不包括全凝器和再沸器，进料板从塔顶 **1** 开始，结果最后一行是再沸器。默认设计为 6 块板、进料板 3、1 mol/s、丁烷 0.5、330 K、400 kPa、回流比 2、馏出比例 0.5。

求解器用原生 Rust 联立逐板组分、气液相平衡和焓平衡（MESH），采用同一有限 PR78 物性包；常摩尔流仅作初值。计算成功后独立重算逐板及全塔的组分、能量、逸度和相稳定性，输出各板温度、液/汽组成与流量，塔顶/塔底产品及冷凝、再沸负荷。冷凝负荷为移出热量，再沸负荷为加入热量，单位 W；内能/焓继续沿用原有基准。报告通过数值守恒不代表独立实验验证或真实设备尺寸、塔板水力学、泛塔与效率已完成设计。

可输入范围：进料 0.001–1000 mol/s、丁烷分数 0.01–0.99、温度 293.15–400 K、压力 100–2000 kPa、回流比 0.05–20、馏出比例 0.01–0.99。输入合法不保证存在支持范围内的解；低压富丁烷端可能需要低于物性下限的温度。超出物性范围、夹点附近不收敛、干板或时间预算耗尽时会显示失败，不发布未经审计的部分结果。

设计计算使用独立的后台任务，全服务端最多一个任务、无等待队列，忙时明确拒绝；取消后的工作在退出前仍占名额。它不占用动态工业回路的任务槽，也不在 Godot 主线程或世界锁内求解。关闭面板、取消或断线会使迟到结果失效；编辑输入后旧结果仍对应当时的输入快照。设计输入与报告仅在当前会话保留，不消费或生成世界物料，不放置或运行蒸馏塔，不写工业归档。离线 demo 不提供此工具。

验证入口：`just godot-distillation` / `just godot-distillation-graphics`，后一项启动实际图形窗口；对应 `cargo +nightly -Zscript scripts/godot.rs distillation[-graphics]`。

### 蒸馏塔建造与外部接管（5B）

按 **J** 编辑二元设计和塔径，可保存设计、读取保存设计或将当前参数用于建造。设计文件默认位于 Godot 用户目录的 `column-design.json`，包含文件版本、物性修订、参数和直径；不保存计算结果。导入失败保留原草稿，未知格式、过大文件、非法参数或不匹配的物性修订会被拒绝。保存和建造只要求结构参数合法，数值计算是否成功另行显示。

通过 `/industry kit` 取得“蒸馏塔”，持塔按 **B** 查看建造规格，右键消耗一件设备放置。塔径为 2–6 格，高度为理想板数加 2（4–14 格）；建成后规格固定，需拆建才能更改。塔径仅决定几何、占位和碰撞，不参与理想级分离计算或水力尺寸设计。塔体的三个侧接口分别是进料、塔顶产品、塔底产品，进料高度随进料板改变；可使用现有三维管道和两点铺管连接。

瞄准塔体按 **E** 查看已建设计并检查三罐外部接管：三条线路必须分别连接独立密闭罐，进料线需要朝向塔的一泵一阀，产品线各需阀门。缺管、错向泵、重复罐、回环或不支持设备会给出诊断。报告在结构修改后失效，不写入存档。检查通过仅表示这三条外部线路符合规则，不表示完整冷凝、回流、再沸装置或工艺性能已验证。

本阶段塔体不储存或分离物料；接到塔口的工业管组明确暂停并保留已有库存和能量，其他独立管组照常运行。已建设计随设备保存和多人同步；没有燃料、冷热源、塔板持液或动态开车过程。

验证入口：`just godot-column` / `just godot-column-graphics`，使用隔离测试世界，覆盖设计文件、建造、外部检查、多人同步及保存重开。

## 结构生成

单人和多人在未探索区域生成**村庄与城堡**。村庄包含道路、水井和四间从模板池选取的木屋/石屋；城堡包含城门、四座塔楼、城墙、庭院及带内部楼梯的两层主楼。入口为开放洞口，楼梯为可跳上的整格台阶。结构使用现有方块，支持既有碰撞、破坏收取、放置、多人同步与保存；本阶段不生成村民、战利品箱、交易或攻城事件。

参考 [Minecraft Structure definition](https://minecraft.wiki/w/Structure_definition) 的生态、生成阶段、地形适配和模板池分工，以及原版村庄的 [结构定义](https://raw.githubusercontent.com/misode/mcmeta/data/data/minecraft/worldgen/structure/village_plains.json) / [结构集](https://raw.githubusercontent.com/misode/mcmeta/data/data/minecraft/worldgen/structure_set/villages.json)。本项目使用自己的 JSON 子集与方块模板，不兼容 Minecraft 数据包、NBT 或完整递归 jigsaw。

- `server/assets/structures/definitions.json` 定义区域间距、分离距离、盐值、结构权重、生态、坡度限制、整平范围和模板组合。
- `server/assets/structures/templates.json` 定义可复用模板：按顺序执行包含端点的方块长方体填充，支持显式空气、四向旋转与加权模板池。方块名沿用 `protocol::BLOCK_IDS`。两个 JSON 随 Rust 二进制嵌入，修改后重新构建；启动时验证格式、引用、边界和方块名，非法配置报错。无需运行时下载资源。
- 默认每 24×24 区块区域选一个候选锚点，分离参数 8；符合生态的结构按村庄 3、城堡 1 加权选择，随后拒绝水域、陡坡与越界位置，因此不是每个候选都会落地。结构覆盖最多 49×49 格，内部整平，外缘 4 格渐变；只填充表层地基，保留深层洞穴。
- 按种子和绝对坐标计算完整计划，仅写当前新生成区块；正负坐标、探索顺序、分批保存重开都保持一致。结构直接保存为普通方块，沿用区块版本 3，无独立结构存档。已探索区块与玩家改造不回填、不重建；旧探索边界处可能出现部分结构/地形接缝，向完整的未探索区域探索可看到完整建筑。未来更改生成定义也只影响新生成区块。

```sh
just godot-structures
```

该命令在 `target/` 隔离存档中使用默认种子 12345，访问正负坐标的两类结构，验证真实 QUIC 区块流送、网格卸载、缓存限制与保存重开，并输出 Forward+ + SDFGI 截图和指标到 `target/structures-graphics-*/`。测试坐标由 Rust 测试计算并写入 `target/structure-sites.json`。默认种子下可先 `/fly on`，再 `/tp 66 57 -520` 俯瞰城堡，或 `/tp -562 66 936` 俯瞰村庄；已探索旧区域不会自动出现建筑。

## 网络与存档

- 默认监听 `127.0.0.1:9876`；局域网可设置 `CDDA_BIND=0.0.0.0:9876`。
- 服务端每次启动生成 TLS 证书，默认写入 `save/server.cert.der`，可用 `CDDA_CERT_PATH` 改路径。客户端必须使用服务端本次生成的证书，不跳过验证；远程玩家通过 `--cert FILE.der` 指定证书。
- 协议版本为 **17**，新增蒸馏塔设计与三罐接管报告；保留有界蒸馏设计请求/取消/结果消息；保留罐体规格和换热单元检查命令/回执；保留管道接头、管架及两点铺管；保留密闭罐、双流换热、128 格高度、飞行、区块列卸载、客户端稳定 UUID、镜头朝向和物品栏版本校验。版本 16 及更旧客户端不能加入，客户端与服务端须同时更新。世界存档为版本 13。
- `World3d.seq` 是该玩家最后**执行**的输入序号。客户端只有在有界发送队列接受输入后才预测；收到快照先应用权威位置与速度，再重放未确认输入。客户端最多保留 16 条未确认输入（包含传输中的输入），与服务端输入队列容量一致；达到上限时暂停发送和预测，收到执行确认后恢复，避免服务端卡顿或网络延迟导致正常客户端积压断线。服务端每 tick 最多消费每人一条输入，拒绝无效数值、乱序和超量积压。
- 慢客户端的队列不能阻塞广播；网络读取任务持续拥有接收流，不会被 UI 的发送取消。客户端每帧处理网络消息数量有上限。
- 默认存档为 **`save/world3d.bin`**，保留 `DNG3D001` 标记，格式版本 **13**。MessagePack 清单保存高度、种子、已生成区块列坐标和归档引用；区块、玩家、生物实体及工业设备分别位于 `world3d.chunks/`、`world3d.players/`、`world3d.entities/`、`world3d.industry/`，文件名均为 `<同一批次 UUID>.rkyv`，由 rkyv + memmap2 读写。先写完并同步四个不可变归档，再原子替换世界清单；保存中断仍加载上一个完整批次。工业归档版本 **6**（`DNGIND06`）保存蒸馏塔设计、设备稳定身份、罐体规格、朝向、显式管接头、控制、组分摩尔数、内能、物性修订、下一设备 ID 和完整交换账目。烃能量允许为负，内部换热不记成外部热源。运行读数、管网拓扑、铺管草稿与会话请求缓存不持久化；每世界最多 1024 台设备。
- 读取版本 1 地图时验证并补箱，备份为 `world3d.v1.bak`；版本 2 保留箱子，备份为 `world3d.v2.bak`；版本 3–6 验证其原有归档后备份为对应 `.vN.bak`，独立复制存在的归档目录。已有不同备份时使用编号后缀。补箱优先位置为 `(26, 7, 30)`，被占用则选择安全空位，不覆盖原方块。备份失败或无安全空位则停止加载，原文件不变；下一次成功保存才升级到版本 13。版本 1–4 没有怪物记录，迁移时按原规则初始化三只怪物，此后保存其状态和死亡后的缺席。版本 5 及以上保留既有怪物缺席记录，原区域不会重新生成。
- 原来的 `save/world.bin` **不会自动迁移或覆盖**。把二维文件传给 `CDDA_SAVE_PATH` 会明确报错并停止启动；若要继续保留旧二维地图，先保留原文件，再使用新的三维存档路径。当前没有二维到三维迁移命令。
- 当前持久化地图、箱内物品、地面物品、怪物，以及所有已访问角色的生命、位置、速度、朝向、背包槽位和选中快捷栏；离线角色也会保留。每 30 秒、玩家断线及服务端正常退出时共同保存。强制终止最多回退到上次成功提交的批次。怪物恢复原位置、运动、朝向、生命、UUID、网络 ID 和攻击冷却；已击杀怪物不会在读档时重新生成。玩家恢复位置被地形或其他实体占用时改用安全出生点，保留背包；玩家死亡状态按原有规则复活。
- 客户端首次连接在 Windows `%APPDATA%/Dungeon3D/client.uuid` 生成随机 UUID，可用 `CDDA_IDENTITY_PATH` 指定独立身份文件。改昵称仍恢复同一角色，同名不同 UUID 相互独立，同一 UUID 同时上线会被拒绝。身份文件损坏会明确报错，不会自动换号；换电脑需复制原身份文件。这是角色标识，不是账号认证。
- 版本 7 完整验证后备份为 `world3d.v7.bak`，对应归档独立复制到 `.v7.bak.chunks/`、`.v7.bak.players/`、`.v7.bak.entities/`；工业状态初始化为空。版本 1–6 保留原迁移规则，最终在下一次成功保存时写入版本 13。回退时恢复旧版清单及其完整归档目录。
- 版本 8 使用工业 v1 的精确 rkyv 布局读取，完整验证后备份清单与四类归档为 `.v8.bak*`。原设备 ID、朝向、物料和内能保留；补默认控制和从零开始的历史账目。未知旧物料保留并暂停计算。
- 版本 9 使用工业 v2 的精确布局读取，备份为 `.v9.bak*`。旧水库存、控制和账目保留；新增热设置为空、烃与加热账目为零。版本 10 使用工业 v3 的精确布局读取，备份为 `.v10.bak*`，原热库存、内能、控制、物性修订和账目均保留；旧管接头缺省为空，继续按原轴向解释。版本 11 使用工业 v4 的精确布局读取，备份为 `.v11.bak*`，补默认罐体规格并保留显式管接头、热库存与全部账目。版本 12 使用工业 v5 精确布局读取并完整备份为 `.v12.bak*`，原罐体规格、热库存、控制与账目保留，旧设备的塔体设计为空。版本 1–12 最终均保存为版本 13，旧程序不能读取新版。
- 手动备份版本 13 时须一起复制清单及四类归档目录；旧批次不自动清理。损坏、缺失、批次不一致、未知设备、重复身份、非法数值或重叠均阻止加载。只有同格一根水平管与一个单管架可共存，重复管/架及其他重叠都拒绝。工业归档绑定 `butane-pentane-pr78-cp298-r1` 物性修订，不匹配时拒绝加载，不能用新公式解释旧内能。

单人模式同样使用 `save/world3d.bin`（相对于启动工作目录），可通过 `CDDA_SAVE_PATH` 指定其他路径。返回主界面、菜单退出和窗口关闭都会先等待后台共同保存、关闭本地服务端并清理网络任务；保存错误会显示在菜单中而不会自动退出。独立服务端和单人模式使用相同的排他世界锁，阻止同时打开同一存档。内置证书只在内存中传递，不覆盖独立服务端的证书文件。

客户端参数：`--server IP:PORT`、`--cert FILE.der`、`--name NAME`、`--connect`、`--singleplayer`、`--demo`、`--capture FILE.png`、`--capture-frames 1..4096`（默认 64）、`--lighting gi|direct`（默认 gi）、`--fov 55..100`（默认 72°）、`--yaw DEGREES`。直接运行 Godot 或导出程序时，游戏参数放在 `--` 后；通过 `scripts/godot.rs` 时由脚本添加。相对证书路径相对于进程工作目录，远程/导出运行建议使用绝对路径。

`--capture` 配合 `--demo`、`--connect` 或 `--singleplayer` 时，在完整区块数据和玩家状态到达后累计指定帧数，让光照历史收敛，再截图并退出；整体 120 秒未完成则报错。未指定游戏模式时截取主界面。设置页可开关 SDFGI；关闭后仍使用 Forward+，不是切换到兼容渲染器。`CDDA_RUN_SECONDS` 可使测试服务器定时正常退出。

## 模块边界

### 动态区块同步

参考 [Minecraft 区块同步](https://zh.minecraft.wiki/w/Java版网络协议/区块同步) 的附近加载与显式卸载思路，仍使用本项目的 Quinn/QUIC 和 MessagePack，不实现 Minecraft 协议兼容。

- 服务端以权威玩家所在 X/Z 区块为中心，提前加载半径 3 的 7×7 区块列；每列高 128。优先发送最近区块，每玩家每 tick 最多 8 条加载/卸载消息（最多 1 个区块列，常规流送全服每 tick 最多生成 2 个新列，轮换玩家优先级），为快照保留队列空间。客户端附近 3×3 区块列到齐即可进入游戏，无需等待全图。
- 玩家移动导致加载窗口变化时，先显式卸载离开窗口的客户端区块，再发送新范围内的数据。已生成区块直接复用；未生成区块根据种子和世界坐标生成，树冠跨区块查询，不受探索顺序影响。客户端最多缓存 49 列、392 个分段；未知空间继续阻挡移动。
- 方块编辑只通知已收到该区块的玩家；后来进入范围的玩家获得最新完整区块。加载、编辑、卸载均刷新对应网格及相邻面的可见性，Godot 删除卸载网格、复用无变化节点。断线和新会话清空缓存。
- 地形显示使用去重的待更新队列，优先玩家附近，每帧最多重建 2 个分段，目标 CPU 预算 2 毫秒（单个分段不可中断，可能略超预算）。卸载立即删除节点并取消待更新项，切换会话清空队列；没有新网络修订时也继续处理。碰撞数据立即更新，远处网格可稍后显示，自动截图等待队列清空。Rust 网格生成缓存相邻分段引用，顶点属性一次分配后通过切片批量写入 Godot 数组，避免逐顶点引擎调用；不降低视距、材质或 GI 设置。
- 当前服务端将所有已探索区块保留在内存中，每个存档批次仍整体写入稀疏归档；内存和保存成本随探索增长，尚未实现服务端区块驱逐或按区域增量落盘。沿用单归档 64 MiB 的保护限制，超限会明确保存失败并保留上次完整存档。
- `--demo` 仍为固定区域离线展示；单人游戏和多人服务器均使用动态生成。

区块流送的图形回归可执行 `just godot-streaming`：先用真实 QUIC 在隔离平坦跑道上走过 x=64 和 x=0、保存重开，再启动 Forward+ 图形窗口，从保存的负坐标位置继续跨区块移动。验证新区块网格出现、旧节点删除、缓存不超过 392 个分段和退出保存；截图位于输出的 `target/streaming-quic/<UUID>.streaming.png`。该脚本注入移动输入，不代表手动键鼠或长时间探索验收。

`just godot-streaming-perf` 在实际图形窗口、隔离存档中执行近距离/远距离传送和 7 秒加速飞行，记录主线程、地形更新和整帧的 p50/p95/峰值，同时检查每帧更新上限、队列排空、卸载和会话清理。结果与截图位于 `target/streaming-perf-<标签>-<编号>/`；`CDDA_PERF_LABEL` 设置标签，`CDDA_PERF_GI=on|off` 只覆盖本次测试的 SDFGI，不写入用户设置。不指定时使用当前设置；比较前后性能时保持渲染设置相同，避免同时运行其他游戏或构建。短时测试不保证所有场景下的帧时间。

### 区块数据编解码

`server::chunk_data` 参考 [Minecraft Chunk format](https://minecraft.wiki/w/Chunk_format)，采用 `DataVersion`、区块坐标、`Status`、`LastUpdate`、`sections` 和 `block_entities` 的组织方式。本项目按探索范围保存稀疏的 16×16 区块列，每列八个 16³ 分段；这是项目自己的 rkyv 格式，不是 NBT/Anvil 文件，也不提供 Minecraft 地图导入。

每个分段用稳定的 `game:*` 方块名称调色板和 u64 压缩索引保存，索引顺序为 `y*256+z*16+x`。单一方块无需索引数组；其余至少 4 位，索引不跨 u64 边界。箱子作为所属区块的方块实体保存位置、修订号和物品，地面物品同样归属区块列。空分段也显式记录，缺失数据视为损坏。归档不保存生物群系或光照缓存，生态只在首次生成时决定；未探索区块不写入归档，已生成区块必须与世界清单一致，缺失时拒绝加载。

区块文件使用 `DNGCHK01`、16 字节头、版本 3（兼容读取旧版本 1/2）、little-endian/32 位归档指针布局，与玩家共用映射 IO。Windows 保持文件句柄直到映射释放，禁止映射期间写入或删除；其他平台使用匿名映射副本。读取先进行 rkyv bytecheck，再检查区块完整性、调色板、压缩长度、实体归属和箱子方块对应关系。运行时使用稀疏分段网格，网络消息使用协议 12 的 MessagePack。

### 实体数据编解码

`server::entity_data` 参考 [Minecraft Entity format](https://minecraft.wiki/w/Entity_format) 的类型、UUID、Pos、Motion、Rotation、OnGround 和 Health 字段组织，沿用项目自己的 rkyv 格式，不支持 Minecraft NBT 导入。当前生物类型为 `game:zombie`；玩家继续使用独立玩家归档，箱子与地面物品继续保存在区块归档。

实体归档包含 DataVersion、Dimension、批次 UUID、种子、世界 tick，以及按 X/Z 区块列组织的实体列表。全部已生成区块列均显式记录，包括空列表，并与地形区块集合核对；怪物越过区块边界后按当前坐标归档。UUID 与 NPC 网络 ID 均唯一，网络 ID 保持高位命名空间，hecs 句柄不落盘。位置和速度以 f64 存储并恢复为运行时 f32，速度单位为米/秒，角度为弧度；另存生命上限、落地状态和最后攻击 tick，随世界时钟共同恢复，离线时间不推进模拟。当前怪物没有俯仰，Rotation 第二项固定为 0；AI 追踪目标在上线后重新计算。

文件使用 `DNGENT01`、16 字节头和版本 2 数据（兼容读取旧版本 1），沿用 little-endian/32 位归档指针布局和映射 IO。读取先做 rkyv bytecheck，再检查元数据、完整区块集合、坐标归属、类型、UUID/网络 ID、有限数值、生命范围与冷却 tick。实体文件必须与清单和区块归档的批次、种子及世界 tick 一致。空世界不会补怪，缺失文件会报错。

### 玩家数据编解码

`server::player_data` 参考 [Minecraft player.dat](https://minecraft.wiki/w/Player.dat_format) 的字段组织，使用固定版本 `rkyv 0.8.18` + `memmap2 0.9.12`。这是本项目的归档格式，不支持直接导入或导出 Minecraft NBT。

记录包含 `DataVersion`、UUID、名称、Dimension、Pos、Motion、Rotation、OnGround、Health、Inventory 和 SelectedItemSlot。Inventory 仅存非空槽的 `slot/id/count`，保留 0–8 快捷栏和 9–35 背包的空隙，每格最多 64 个；当前物品名称作为项目内物品标识。SelectedItemSlot 为 0–8，不重复保存手持物品。位置用 f64，运行时还原为现有 f32；速度与角度保留项目单位（米/秒、弧度），生命上限保留 100。

`capture/restore` 转换运行时数据；`write_new/read` 读写不可覆盖的玩家归档。文件使用 `DNGPLY01` 标记、长度头、版本 1 数据及固定 little-endian/32 位归档指针布局。Windows 使用文件映射、写入 flush/sync、排他写入和只读映射保护；其他平台读取使用匿名映射副本。读取经过 rkyv bytecheck 和字段范围校验，错误文件不会被重写。恢复后仍需由世界检查碰撞，连接序号和物品栏版本不持久化。

已接入稳定 UUID 登录、同角色重连、改名、周期保存、断线与关闭保存，以及箱子/玩家/地面物品的一致提交。UUID 文件读写在客户端后台网络线程执行；权威存档在服务端处理，Godot 主线程不执行文件读写。测试使用 `target/` 下隔离的世界与身份文件。

### 共享物理

`simulation/src/physics.rs` 使用固定版本 `rapier3d = 0.36.1` 的 `KinematicCharacterController` 和形状扫掠。保留角色盒形尺寸（宽 0.58、高 1.75 米）、移动速度、跳跃和重力；水平移动与垂直移动分别求解，支持贴墙滑动，关闭自动跨台阶与向下吸附。Godot 继续只呈现 Rust 模拟结果，玩家和 NPC 不再经过旧的手写分轴子步碰撞求解器。

每个固定步从当前地形和实体快照构造覆盖移动范围的局部查询；邻接方块合并为盒形碰撞体，减少平地和墙面接缝阻滞。未知格与世界外侧仍是实体障碍，方块增删在下一步立即生效。查询状态不跨步保留，权威纠正及未确认输入重放不会复用旧碰撞缓存；实体按坐标稳定排序，启用 Rapier `enhanced-determinism`，但不据此承诺整套游戏跨平台逐位确定性。

此接入使用运动学角色，不新增刚体堆叠、掉落物弹跳或布娃娃。方块放置和出生恢复的占位检查仍使用同尺寸 AABB；Rapier 接入本身不修改存档与协议消息格式。客户端与服务端应一同更新，旧程序的运动预测不保证与 Rapier 版本一致。
